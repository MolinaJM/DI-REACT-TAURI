BLOQUE 5. TAURI (6 h)
--------------------------------------------------------------------------------

OBJETIVO: Empaquetar la SPA en una app de escritorio nativa.

TEORÍA (3 h):
  5.1  ¿Qué es Tauri? Webview + binario Rust.
  5.2  Estructura src-tauri: tauri.conf.json, Cargo.toml, main.rs, build.rs.
  5.3  Configuración de la ventana: título, tamaño, resizable.
  5.4  Integración con Vite: beforeDevCommand, devUrl, frontendDist.
  5.5  Host Rust mínimo: tauri::Builder + generate_context!.
  5.6  Ciclo de compilación: TypeScript/Vite (dist) + Rust (binario).
  5.7  Empaquetado y distribución: tauri build.
  5.8  Dependencias del sistema en Linux (webkit2gtk, libsoup) y resolución de
       problemas (OOM con CARGO_BUILD_JOBS=1).
  5.9  Comunicación app <-> Rust: comandos invocables con invoke y estado
       compartido (ApiClient con reqwest para el HTTP hacia Spring Boot).
       * listar_peliculas, buscar_peliculas, crear_pelicula,
         actualizar_pelicula, eliminar_pelicula.
  5.10 Diálogos nativos con @tauri-apps/plugin-dialog:
         * confirm() en el borrado de películas.
         * save() para exportar a JSON.
         * open() para importar desde JSON.
  5.11 Acceso al sistema de archivos mediante comandos Rust (exportar_peliculas
       escribe el JSON con std::fs; importar_peliculas lo lee).
  5.12 Permisos y capabilities: src-tauri/capabilities/default.json
       (core:default, dialog:default) y plugin registrado en main.rs.
  5.13 Flujo de trabajo normal con Tauri (práctica profesional):

       En la mayoría de proyectos profesionales con Tauri:

       1. La UI se desarrolla como web normal (Vite dev server en navegador).
          Se prueba la interfaz, componentes, estilos y lógica de UI en
          http://localhost:1420 con HMR y DevTools.

       2. Se conecta a un backend real (API REST) directamente con fetch.
          El frontend se comunica con el servidor sin depender de Rust.
          Esto hace que la app funcione en cualquier navegador.

       3. Se añaden plugins de Tauri solo para lo que NO se puede hacer en web:
          dialogs nativos (confirm, save, open), tray icon, notificaciones,
          acceso a archivos con std::fs, etc.

       4. Se empaqueta con Tauri para distribuir como app de escritorio.
          El resultado final se distribuye con tauri build.

       Es decir: la app se comporta como una web normal, y Tauri se usa como
       contenedor para añadir features nativas.

       En este proyecto se implementa un enfoque híbrido:
       - El servicio PeliculaService detecta el entorno con isTauri():
         * window.__TAURI__ existe → estamos en Tauri → usa invoke (Rust).
         * window.__TAURI__ no existe → estamos en navegador → usa fetch.
       - App.tsx usa dialogs nativos en Tauri y fallbacks (window.confirm,
         Blob download, FileReader) en navegador.
       - Así la app funciona tanto en http://localhost:1420 (navegador)
         como en la ventana de escritorio (Tauri).

PRÁCTICAS (3 h):
  - P1: Configurar una ventana de 1100x720 y lanzar npm run tauri dev.
  - P2: Crear un comando Rust (saludo o lectura de archivo) e invocarlo con

  - P3: Conectar el frontend a la API REST con fetch (funciona en navegador).

RESUMEN DE CONCEPTOS IMPRESCINDIBLES (cheat-sheet)
--------------------------------------------------------------------------------

  Typescript: interfaces | opcionales (?) | generics | utility types
              | Record | type assertions | módulos | strict mode
  React:      componentes | props | useState | useEffect | useCallback
              | useRef | lifting state | listas+key | render condicional
              | forms controlados | fetch asíncrono | modal | debounce
  Tauri:      tauri.conf.json | ventanas | devUrl/frontendDist | main.rs
              | invoke + comandos Rust | reqwest | capabilities/permissions
              | @tauri-apps/plugin-dialog (confirm/save/open) | std::fs | build
              | isTauri() + fetch (enfoque híbrido) | window.__TAURI__
  Transversal: arquitectura cliente-servidor | CORS | UTF-8 | CRUD | Docker
